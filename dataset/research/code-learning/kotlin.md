# Kotlin Kexer fine-tuning

## agen-codexfer-kotlin7b

The [original technical report](https://arxiv.org/html/2405.19250v1), TableII, reports CodeLlama7B improving26.09%→42.24% on161expert-translated Kotlin HumanEval problems. The [model card](https://huggingface.co/JetBrains/CodeLlama-7B-Kexer) instead says26.89% initially;26.09% agrees with42/161and the paper's complete outcome distribution, so use the paper. Final42.24% is68/161. Greedy generation uses128–256new tokens and answer cleanup. The human endpoint is comparable one-submission function correctness, not the technical report's expert translators' ability.

This is actual weight updating but partly instruction/format learning. The paper explicitly discusses this explanation: first-line completion falls0.388→0.344 while syntax-error rate improves22.98%→19.25%. The point must not imply clean evidence of acquiring Kotlin from zero. [human-learning.md](human-learning.md) estimates8hours, sensitivity3–24, for a learner with Java/Python and rudimentary Kotlin to improve short function writing. This is an assumption informed by Koans and inspected task content, not a measured8-hour course result.

The model card reports15,000examples/~3.5million tokens over4epochs:14million training tokens. The central update estimate is6×7B×14M. The [training-data card](https://huggingface.co/datasets/JetBrains/KExercises) and report identify GPT3.5-generated Python exercises translated by GPT3.5-Turbo; count these helpers too. The estimate allocates creation of the15,000selected Python items, plus translation, not the whole unrelated Jina corpus. Per item, assume100prompt+230output tokens to create Python and25instruction+230Python-input tokens to translate; Kotlin output totals3.5million. Apply1.25for unrecorded extra generation/selection. These are assumptions, not recovered API usage.

The unidentified GPT3.5 snapshots use7B active parameters as a family transfer from the current shared registry's conditional output-rank estimate for0125; the older generator is not known to be that snapshot. A175B alternative is retained in the wide compute sensitivity, together with2×more helper work. This source ambiguity matters more than rounding the fine-tuned7B model size. The helper parameter calibration originates in [Stealing Part of a Production Language Model](https://arxiv.org/html/2403.09539v2#S4); it is not an official architecture disclosure.

For checks during training, assume four passes of the630source-defined completion-validation cases and161HumanEval cases at512total tokens each. This is a modest explicit monitoring estimate; neither evaluation cadence nor all exploratory dataset-size experiments are logged. Full unrelated hyperparameter sweeps are not included. Arithmetic and scenarios are in [calculate.py](calculate.py).

The model repository has a May21,2024 initial commit; the [author announcement](https://blog.jetbrains.com/kotlin/2024/05/ai-friendly-programming-languages-the-kotlin-story/) is dated May30.
