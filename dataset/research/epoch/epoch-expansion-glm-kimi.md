# Epoch GLM and Kimi native runs

This tranche applies the reviewed human recipes for [GPQA](gpqa.md), [OTIS](otis.md), [SimpleQA-Verified](simpleqa.md) and [SWE-bench](swebench.md) to original native evaluation logs. It adds no human timing observations or revised human numbers. Cache reads are removed from inclusive input; reasoning remains inside native output. Every nonempty sample's counters are checked individually. The primary workload includes all recorded work and is divided by the source header completed count, including where unscored records contain primary usage. Repeated evaluation epochs are not a best-of-N solving strategy.

## Model sources

- **GLM-5**: [original model card](https://huggingface.co/zai-org/GLM-5) reports 744B total and 40B active, giving 80B FLOPs per processed token. The original public model repository [discussion 1](https://huggingface.co/zai-org/GLM-5/discussions/1) thanks the team for its release on February 11, 2026, and a [contemporaneous coding-client issue](https://github.com/anomalyco/opencode/actions/runs/21917615748) says the model is available that day. The official [release notes](https://docs.z.ai/release-notes/new-released) are dated February 12. We record the earlier evidenced public-availability date, February 11, and do not infer dates merely from repository creation. Sparse attention overhead is outside the common coefficient; the attention term itself is carried in `compute_flops` (`research/attention-correction.md`).
- **GLM-4.7**: [NVIDIA's implementation documentation](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/main/docs/models/glm/glm47.md) identifies the full model as approximately 358B total, 32B active. This is the implementing library's explicit architecture count, not a parameter rumor. [Original configuration](https://huggingface.co/zai-org/GLM-4.7/blob/main/config.json) confirms 92 layers, 3 dense layers, 160 routed experts, top-8 activation plus one shared expert. [Official release notes](https://docs.z.ai/release-notes/new-released) date release to December 22, 2025. Coefficient 64B FLOPs/token; not the much smaller GLM-4.7-Flash.
- **Kimi K2.5**: [original model summary](https://huggingface.co/moonshotai/Kimi-K2.5#2-model-summary) gives 1T total, 32B activated parameters and a separate 400M vision encoder. These runs are text-input tasks and use 32B active language-model parameters, coefficient 64B FLOPs/token. [The original help page](https://www.kimi.com/en/help/agent/agent-overview) and [research index](https://www.kimi.com/en/blog/) explicitly date public release to January 27, 2026. The advertised swarm is not assumed used: the actual Epoch run uses a bash agent for SWE or plain generation for SimpleQA, and all execution calls are to the recorded primary model. No swarm multiplier is applied.

Original model cards and configurations were downloaded freshly under agent-work/sources/model-cards. New model notes contain intrinsic model qualifications only; benchmark execution details are in point notes.

## Missing records and scoring

GLM-5 SWE records 484 unique tasks and all their primary usage, but only 462 are scored (333 C, 129 I, 22 with no score). The per-summary completed flag is true even for the unscored records; therefore the denominator follows the source header rather than counting that flag. Retaining the 22 records' actual usage avoids dropping model work because grading failed. The human effort recipe remains the exact 484-task workload mix. The source score is 333/462; it is not represented as 333/484.

Full-sample review found that missing counters do not mean zero model work. Across five GLM runs, 36 records retain substantive reasoning despite blank final answers; eight length-limit exceptions contain exact native prompt, completion and cached-token counters, each with 128,000 completion tokens; five records end with transport failures. The retained record-level recovery audit is in `agent-work/sources/epoch/legacy-accounting/expansion-04/usage-recovery.json`. Retained reasoning and text are counted once with the [original GLM-4.7 tokenizer](https://huggingface.co/zai-org/GLM-4.7/blob/main/tokenizer.json) or [original GLM-5 tokenizer](https://huggingface.co/zai-org/GLM-5/blob/main/tokenizer.json), with prompt text tokenized and 12 assumed framing tokens. Unknown prompt cache hits are assumed zero. These tokenizations estimate actual provider token usage; they are not native usage counters.

For calls whose response is lost entirely, impute the same run's mean included tokens across known or recoverable responses. Explicit rate-limit rejections receive zero. One GLM-5 GPQA failed sample has ten distinct timestamped model events: six rate-limit rejections, three timeouts and one ReadError. Another retained-response sample has eight preceding failed events: five rate-limit rejections, two timeouts and one connection error. That initial seven-call estimate was superseded for GLM-5 GPQA by the full-run [traceback audit](epoch-native-usage-audit.md#reas-epoch-gpqa-glm5): connection-establishment failures receive zero; 23 response-read failures receive the known/reconstructed response mean. The preceding event examples describe the initial audit, not the current imputation rule; distinct UUIDs/timestamps identify requests, without also counting error representations. Other transport failures each have one request. It is uncertain whether a timeout/connection error occurred before inference began or after substantial generation; zero through a full response is a plausible range. This modest residual imputation avoids treating lost responses as measured zero compute. All five affected rows are derived_assumed_inputs. The eight errors with exact native counters are recovered without mean imputation. This audit targets zero-primary-usage summaries. Nonzero summaries may also omit earlier failed requests; absence of such omissions is not established by summary counter identities. A bounded independent nonzero spot-check is recorded in epoch-native-usage-audit.md. Raw original counters remain alongside the corrections, and the pre-correction submission is frozen in expansion-04/before-usage-recovery.

GLM-5 SWE's unit is total compute expended per completed evaluation: all 484 submitted issues contribute actual work, allocated over 462 completed evaluations, including 129 incorrect patches. This is not compute per successful patch and is not a literal average restricted to the completed issue subset. The human baseline continues to describe the full submitted task mix; incomplete evaluations' cost is treated as overhead per completed evaluation. Native score 333/462 remains unchanged. For multi-epoch runs, native accuracy can differ from raw correct/completed because source scoring first reduces scores by question; both quantities remain in calculations.

For the two SWE runs, 72.1–73.8% native test success is judged below the same conditional correct-deliverable target as the reviewed first tranche. This is a qualitative transfer within the same source-defined tasks and assessment, not an assumed measured human solve probability. The benchmark-wide inspection of test defects and substantive model errors in swebench.md limits the magnitude one can infer. GLM's own `django__django-13112` failed patch summary additionally describes changing migration `resolve_relation`, the wrong-path issue identified in the earlier review. Kimi does fix both paths on that example; no model-specific failure is inferred from another model's patch. All failed model work remains in compute, whereas the human estimate targets eventual correct work.
