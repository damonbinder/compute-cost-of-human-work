# AI Village: three software artifacts

These observations cover a personal website, a local puzzle prototype and a benefits-screener prototype. Each has a defined endpoint and inspected output. They do not measure completion of the Village's broader publicity or poverty-reduction goals.

The original sources are the [Village replay](https://theaidigest.org/village/timeline), its public event/session APIs, original screenshots and delivered files. `agent-work/sources/village-expansion/manifest.json` records URLs and hashes. `selection.json` identifies every included session and exact controller window. Unselected downloads are retained outside the published sources. Agent claims are checked against artifacts where possible.

## Accounting

`calculations.json` retains every included model call, native counters, excluded cache reads, duplicate events, helpers and scenarios. All failed tool actions and repairs inside the selected implementation sessions remain included. This counts inference, including coding assistants and estimated memory summaries; it excludes prior model training and unrelated Village work.

For Gemini, the native identity is `gemini-2.5-pro-preview-06-05`. Each response satisfies `totalTokenCount = promptTokenCount + candidatesTokenCount + thoughtsTokenCount`. Cached content is part of the prompt and is subtracted once. Native modality fields also identify cached versus fresh image positions. Thought tokens are included once in output. The computer sessions have 107 counted calls and four synthetic initial mouse moves with no model usage.

For Opus, count `input_tokens + cache_creation_input_tokens + output_tokens`. Exclude `cache_read_input_tokens`. The puzzle has 34 model calls; the screener has 302. Nine synthetic initial mouse moves in the screener and one in the puzzle have zero usage. Chat copies of computer calls are excluded. Controller events with matching actor/counters within one second are deduplicated, usually a START/WAIT event followed by a TALK event from the same response.

Controller events export only scalar input/output counts. Gemini's scalar input is a full prompt; the Anthropic scalar omits separate cache fields. The central estimate retains those counters without pretending the missing breakdown is observed zero. The research includes no-controller-input and doubled-controller-input scenarios. Missing breakdowns can mean overcounted reads or omitted creation; there is no universal direction for this component. Gemini controller reasoning is also absent, so add an assumed 100 reasoning tokens per distinct controller call, approximately the scale of the native computer-call thinking. This is not a measured counter.

The organizers describe a separate consolidation prompt in [How the AI Village works](https://aivillageblog.substack.com/p/how-the-ai-village-works). The exported long session summary is not accounted for by its much shorter STOP-action output. Estimate one extra summary call per included session: last full input plus last output as input, and tokenized summary text as output. Its cache breakdown and exact prompt are unavailable. Full processing of that context is the central assumption. Zero extra summary calls and twice its input are separate scenarios.

### Coding and coordinate helpers

The three Gemini coding commands preserve full Codex v0.46.0 stderr and native totals: **1,454 + 14,191 + 5,672 = 21,317 text tokens**. The retained original [Codex protocol](https://github.com/openai/codex/blob/rust-v0.46.0/codex-rs/protocol/src/protocol.rs) defines `blended_total` as noncached input plus output. Its [human-output implementation](https://github.com/openai/codex/blob/rust-v0.46.0/codex-rs/exec/src/event_processor_with_human_output.rs) prints that value as “tokens used.” No second cache subtraction is applied.

Opus invokes Codex through a graphical terminal. The commands are retained, but final counters are not visible in a bounded inspection of 54 original terminal screenshots. The missing-work recipe is **3,000 setup/reasoning tokens + tokenized command + 3 × written-code tokens** per invocation. The multiplier allows generation, one subsequent code read and further editing/checking; it is an assumption, not a reconstruction of hidden calls. The original native website helper's 14,191-token workload for a roughly 3,000-token HTML artifact provides a scale check. Missing helpers contribute approximately 1.9% of the puzzle's FLOPs and 0.7% of the screener's FLOPs. Half and double their estimated work are retained.

The puzzle helper writes the original 7,046-token HTML. For the screener, the final four application files contribute 10,001 tokens; vendor React code is excluded. The five earlier helpers use actual requested component text where available, or explicit size estimates for two JSON files and one short Jest test. Exact inputs are in `helper_written_code_inputs` in the calculation. Screenshot `d6b67fa2…` shows Codex v0.46.0 and `gpt-5-codex` on October 22. The same helper identity is assumed for the adjacent unexported October/November commands.

Gemini makes 33 `get_pixel_coords_of_element` calls. Their implementation/model is not public. Allow one helper invocation per call: the actual short element description, 300 system-prompt text tokens, 32 output tokens and one screenshot. Use the primary Gemini coefficient as an explicit proxy for the unidentified helper. This adds about 2.6% of the row's FLOPs. The zero-helper alternative is retained; it is not the central estimate.

### Images and model coefficients

Text tokens in the CSV exclude image positions. For Gemini, use the native image/cache modality fields; a screenshot adds 258 native image positions. Treating these usage positions as backbone positions is still a physical-compute proxy.

Opus has no modality breakdown. The original screenshots are 1024×768. Net prompt growth after graphical actions has median 1,017 positions in the puzzle and 1,027.5 in the screener. Use a rounded **1,000 positions per screenshot**, place each estimated image span at the end of the new input, and intersect those spans with the native cache boundary. This separates text and image work approximately. Serialized tool text, thinking retention and exact placement are not exported. The current [provider patch description](https://platform.claude.com/docs/en/build-with-claude/vision#resolution-and-token-cost) also gives roughly 1,000 positions at this resolution; it does not establish the historical internal representation. The scalar STOP input receives the last call's image share, capped by its recorded input.

The visual frontend is a **CLIP ViT-L/14-336 proxy**, not a claim about Claude or Gemini architecture. A 1024×768 screenshot is covered by a 4×3 grid of 336-pixel crops. For each crop, count patch projection and 24 layers of attention/MLP arithmetic, with MAC=2, using the retained original configuration. The recipe charges this frontend when estimated image positions are freshly processed, including full-context summary assumptions. One and 24 crops are alternatives. Frontend terms are about 0.7–1.2% of totals. Image-embedding reuse beyond the reported cache and non-neural browser/terminal execution are omitted. Context-dependent backbone attention is carried in `compute_flops` (`research/attention-correction.md`).

The shared **180B active-parameter Opus 4.1 prior** is consistent with the original [bandwidth-based estimate](https://unexcitedneurons.substack.com/p/estimating-the-size-of-claude-opus), which gives 166.7–187.5B under FP8 serving assumptions. **GPT-5-Codex and Gemini use 100B active priors.** The source anchor is [Epoch's GPT-5 estimate](https://epochai.substack.com/p/notes-on-gpt-5-training-compute); transfer to the coding variant and Gemini is explicitly assumed, not provider disclosure. Half/double all active sizes is the main architecture sensitivity.

The June 5 preview has a separate model record dated **2025-06-05**, established by the [original API changelog](https://ai.google.dev/gemini-api/docs/changelog#june-05-2025). It shares the existing Gemini family's numerical prior. No inference about exact weights is needed to copy an explicitly assumed family coefficient.

It differs from the currently served page; the latter is only corroborating evidence. The site includes a placeholder contact address and repeats the agent's unverified diagnoses of interface problems. The task is reproducing the site, not verifying those diagnoses.

The excluded native cache reads total 1,739,780 positions; charging them would raise the estimate to approximately 5.04e17 FLOPs.

**Human time:** **150 minutes (9,000 seconds)** for an experienced web developer producing comparable content and presentation with an editor, browser and hosting account, without AI. Components are 55 minutes for layout/responsive CSS, 35 for organizing/writing the short profile from the brief, 25 for the project/report cards, 20 for browser checks and fixes, and 15 for deployment and URL handoff. Include five October 22 construction sessions (**18:40–20:30:12.928 UTC**) and four October 27 upgrade/deployment sessions (**17:00–18:23:01.604 UTC**). The October 27 output is a four-step React wizard for country, household, income/employment and special circumstances, followed by program cards and application guidance. The surviving same-day redeployment bundle/source map contains **12 program records**, not the agent's claimed “15+.” Its wizard and output match the original first-deployment screenshots. The rules are simple predicates. For example, SNAP is approximated with country and per-person income, while Medicaid uses a flat income rule or selected circumstances. This is an unvalidated software prototype, not a reliable determination of benefits eligibility. ## Reproduction

Install Python 3 and `tiktoken`. From any working directory, supply the published paths and a new output directory:

```sh
python /path/to/research/recompute.py --source-dir /path/to/sources --selection /path/to/research/selection.json --output-dir /path/to/new-results
```

The script verifies source hashes, reconstructs historical HTML, recalculates per-call accounting and writes a fresh `calculations.json`. It does not execute the agents' commands or overwrite sources. Source-specific cache alternatives, helper estimates, frontend choices and model-size scenarios are numeric sensitivity cases, not statistical confidence intervals.
