## game-sc2-alphastar-minute

Sources: [original DeepMind paper](https://storage.googleapis.com/deepmind-media/research/alphastar/AlphaStar_unformatted.pdf), Methods Interface and Architecture, Extended Data Fig.2; [original supplementary archive](https://media.springernature.com/original/springer-static/esm/art%3A10.1038%2Fs41586-019-1724-z/MediaObjects/41586_2019_1724_MOESM2_ESM.zip), detailed-architecture.txt. Both the publisher's page and the archive are retained under agent-work/sources/, including the exact architecture text and bnet.json. Do not substitute the later AlphaStar Unplugged architecture.

Reported: the final agent reached Grandmaster in all three races, above99.8% of ranked players. Inference uses55M weights, a three-layer entity transformer, a spatial encoder, recurrent core and conditional action heads. Entity input is padded/masked up to512 entries. Spatial input128×128 becomes16×16; the location decoder upsamples to256×256. Fig.2 gives mean requested observation spacing369ms, separately from113ms observation-to-action latency. The interface has camera and action restrictions, but structured state and unit selection still differ from human controls.

**Our compute estimate:** count55M deployed weights once, then add the repetitions implied by entity and spatial dimensions. This is not simply2*55M per action. The script exposes every added MAC component, avoids adding the first use twice, and adds attention QK/AV products. Four-convolution-resolution stages, eight128-channel residual convolutions and conditional location decoding dominate alongside entity projection/attention.

Assumptions:512 padded entities are processed even if masked; approximate preprocessed entity width1856; an initial1856→256 projection before the first transformer (not explicitly specified in the supplement);75% of actions use the location head; eight unit selections where applicable. Minor scalar/head work is covered by the55M baseline and a2% elementwise allowance. The conditional-head approximation slightly overcounts the one-use baseline on actions skipping heads. These are explicit approximations to an unavailable execution trace.

Result6.206GFLOPs/observation and an estimated162.60 observations/minute, giving1.009e12FLOPs/minute. This uses requested369ms spacing as start-to-start scheduling because the agent requests its next observation ahead of time; it is not executed-forward-pass telemetry. If113ms were additive, the result would be0.773e12. A256-entity/50%-location scenario is0.614e12; all-location at512 entities1.057e12. These are workload scenarios, not confidence intervals. Direct first-layer Q/K/V projection from1856 features instead of the assumed initial1856→256 projection adds0.786GFLOPs/observation, approximately13%; the point retains the initial-projection convention. The supplement does not settle this implementation choice.

Human60seconds is exact by work unit. `expert` describes a Grandmaster-ranked player, not necessarily one of the world's handful of championship professionals; `match` compares within that rank. Training and game simulation/rendering are excluded. No attempt statistic is implied by the analytic minute.

## Shared retrieval model and computation

[Meta's model card](https://huggingface.co/meta-llama/Llama-3.1-405B-Instruct) establishes405B dense parameters and July23,2024 release. [Llama paper Table3](https://arxiv.org/html/2407.21783v3#S3.T3) gives126 layers and width16,384. Reuse the existing `llama-3.1-405b-instruct` record without changing it.

Our inference recipe is `2*405e9*N + 2*126*16384*N*(N+1)`: dense-weight operations plus causal QK/AV attention, with multiply/add separate. Grouped KV heads reduce projection/cache costs, not the number of query-head attention products. Efficient causal attention omits masked upper-triangle products. Minor norms/softmax are omitted; the dense coefficient also slightly overcounts embeddings. Keys and values are retained within each request, so the prefix is processed once rather than recomputed for every output token. No cross-request prefix-cache reuse is assumed. At128K, ignoring attention would miss about39% of this estimate; both rows therefore use operation_count rather than the shared token coefficient alone.

A human can search the phrase “best thing” or relevant location and read nearby matches. There is no reason to read every essay or memorize the text. The document is already open and searchable; no AI assistance.

**Human judgment:**30seconds to read the query, choose a discriminating search phrase, inspect a few hits and type the short answer. A reasonable10–60second range covers an immediate match versus several irrelevant location hits. This simple UI task does not justify borrowing hours of book-reading time. Human target is a correct answer, giving match by construction to the reported near-perfect task family. No measured human timing or attempt count is claimed. The tools difference is explicit.

Workload assumption:128000 input tokens including the needle/prompt and20 output tokens. This normalizes the source's “128K” endpoint; it is not an exact usage counter. The resulting128020 tokens give1.713636e17FLOPs. Using131072 rather than128000 input tokens would alter the total by only a few percent; short output length contributes little.

## memo-nolima-llama-32k

Sources: [NoLiMa original paper](https://arxiv.org/html/2502.05167v2), Tables3,7–9, §4.1 and AppendixC; [official dataset](https://huggingface.co/datasets/amodaresi/NoLiMa), needlesets/needle_set.json and haystack/rand_shuffle/rand_book_1.txt; [official code](https://github.com/adobe-research/NoLiMa), data/book_haystack.py and evaluation/run_config/multi_test_config_book_32K.yaml. These files or their containing archive are retained in agent-work/sources/. Model revision is Llama-3.1-405B-Instruct; Table3 reports38.0% at32K. Standard outputs are short answers, without requested reasoning.

**Inspection:**58 question variants:16 dietary,12 landmark,18 painting,12 city/country, including reversed sentence order. Examples include dietary implications of cappuccino/Brandade, landmarks in Dresden/Helsinki, paintings associated with museums/countries, and smaller cities such as Witbank and Firminy. The sampled haystack is shuffled literary material, not a coherent novel to summarize. Answer is a character name; none of the exact needle strings are supplied to the human. As a noise check, the first128000characters of retained rand_book_1.txt (an approximate32K-token-sized slice, without the injected needle) contain7 matches for “living”,5 for “lives”,1 for “engineer”, and0 each for “painting”, “vegan” and “lactose”, using case-insensitive substring counts. This supports a small candidate set for sensible descriptive searches; it is not a timing observation or a guarantee for every haystack.

**Human task-based estimate:**300seconds. The reader does not know the hidden clue family. Three reconstructed cases below start with the visible country question and ordinary searches for evidence of being in a place. The searches were performed on the first32000 Llama-tokenized tokens of the retained haystack with a source-template needle inserted at the next newline after its character midpoint. These are task inspections on constructed examples, not retained benchmark runs, blinded experiments or measured human times. The collector had previously read the templates; the proposed search policy uses only the visible question and generic travel/residence evidence, and does not use answer-name lists or knowledge that a particular family is present. Full hit contexts are retained in `nolima-walkthrough-searches.json`.

**Walkthrough1 — “Which character has been to France?” (residence example).** Search France, French and Paris: zero matches. Search visited and travel: zero. Search visit:4 hits, none identifying France; “been to”:3 substring hits, including irrelevant “been totally”, “been too” and San Francisco. A reader then considers where people live, since residence is evidence of having been somewhere: lives has5 hits, predominantly the plural noun; living has9, mostly “living room” or general descriptions. One contains an engineer living in Firminy, named Katie. Only now look up Firminy; the [French government's town-hall directory](https://lannuaire.service-public.gouv.fr/auvergne-rhone-alpes/loire/cae1f083-432b-4136-bb9b-dfacd462ace2) places it in France. Answer Katie. This route permits several failed terms and roughly20 contextual checks, not a first search for engineer or Firminy. Allow about4–7minutes, including choosing the residence strategy and a reference lookup. Nearby text happens to expose the needle in one lives context; the estimate does not depend on that accident.

**Walkthrough2 — the same visible France question (artwork example).** The same country/capital and travel searches fail; lives/living yield13 hits without a useful residence. The reader can also inspect sights a person saw as evidence of a visit: saw gives13 hits. One identifies Stuart seeing the original Impression, Sunrise. The [museum's publication](https://www.marmottan.fr/wp-content/uploads/2021/12/FACEAUSOLEIL-dpV2-BD-MAJ.pdf) establishes the work's home collection in Paris. This is a candidate strong inference, not proof of its exact location on every date; the2013 qualifier merits a second reference search before treating it as conclusive. A cautious reader may abstain if unable to settle a loan history. Allow6–10minutes for the failed residence branch,13 additional contexts and historical-reference checking. Searching painting first would depend on a clue the question does not supply. Searching went is another plausible branch with29 hits: even an unproductive scan of that set can add minutes.

**Walkthrough3 — “Which character has been to Germany?” (institution example).** Germany, German and Berlin give zero hits, as do visited/travel. The same4 visit hits and3 “been to” hits do not locate the character. Search lives (6 hits) as the residence branch; one says Calvin lives next to the European Central Bank. Only then look up that institution: the [ECB address page](https://www.ecb.europa.eu/ecb/contacts/address/html/index.en.html) places its headquarters in Frankfurt, Germany. Answer Calvin. Allow4–7minutes for failed terms, context inspection, strategy choice and verification. The reader is not initially told to search bank or landmark.

For aggregation, classify the visible questions by specificity:16 dietary questions at60seconds;12 named-city questions at240seconds;6 named-museum questions at180seconds;24 broad country/region questions at480seconds. This is `(16*60+12*240+6*180+24*480)/58 = 283.45seconds`, rounded to300. These are judgment allocations, not measured means. Broad queries get eight minutes because choosing an unsuccessful branch is plausible and the three selected examples use only one haystack; they do not establish a universal short search. The sensitivity is roughly120–900seconds for the aggregate, not a confidence interval. The baseline includes ordinary searchable documents and non-AI web references. It assumes a proficient reader uses these tools, not unaided reading of the entire32K-token text.

**Performance convention and an answer-key defect:** retain the published38.0% AI aggregate unchanged. Human target is factual inference from the document plus references, including recognizing when the requested place does not follow; it is not obedience to an unseen benchmark key. Six of58 variants (`0408`/`0408Inv`, `T01_C02`, three questions each) associate seeing the original Girl with a Pearl Earring in2013 with the Mauritshuis, The Hague or the Netherlands. The [Frick's official exhibition record](https://www.frick.org/exhibitions/past/2013/mauritshuis) instead documents its New York exhibition October22,2013–January19,2014 during the Mauritshuis renovation; the [original tour announcement](https://www.frick.org/press/masterpieces_mauritshuis_travel_2013_first_major_us_tour_nearly_thirty_years) also identifies San Francisco and Atlanta. Seeing the painting in2013 therefore does not establish any of those three destinations. These six variants remain in the aggregate and time estimate. A source-aware human may correctly reject their premise and be marked wrong by the benchmark. `different_assessment` records this alongside `different_inputs_or_tools`.

`below` remains a judgment, not a measured human score: simple dietary questions and geographically checkable residence/institution clues, plus the more specific museum queries, make higher factual performance than38% plausible with the allowed search time. No exact human success rate is asserted. Artwork-tour ambiguities and poor search paths prevent assuming all58 are factually resolvable or a100% baseline. This is not match-by-construction or an estimate targeting38% human success.

The example YAML specifies a GPT-4o run, not an exact retained Llama run; it supports the32K setup only. The paper establishes the Llama revision. The code defines32000 haystack tokens before insertion; add an estimated100 for needle, instructions and chat framing, plus10 answer tokens. Assuming equivalent English token counts for this workload gives32110 processed tokens and3.026621e16FLOPs.
